# 結合結果の共通整理・検査

結合後に残った同一平面・同一曲面の継ぎ目が、後続のシェルやフィレットを妨げる場合があります。`fuseSolids` と `fuseSolid` ではブール結合を完了した後、`finalizeUnion` で保存・後続加工へ渡す形状を整理します。

## 採用条件

- 元の結合結果をシリアライズし、独立したコピーで整理とメッシュ検査を行います。元ボディの共有トポロジーや三角形キャッシュに検査結果を書き込みません。
- 面と辺の同時整理、面だけの整理の順に試します。入力保持モードを使い、線形許容差は既存の `MODEL_PRECISION.topology`、角度許容差は `MODEL_PRECISION.angular` を使用します。
- CADの有効性、ソリッド数、体積、表面積、外接範囲を照合し、面または辺が減った候補だけを採用します。体積・表面積の差は相対上限に加えて絶対上限1e-6を設けます。大きな回転体で整理による積分値の差が出る場合も、無理に採用しません。
- 候補の全ての面にメッシュが存在し、平面の面積などが整合することも確認します。
- 整理候補を採用できなければ、元の結合結果の独立したコピーを同じCAD・メッシュ検査に通して使用します。それも検査に失敗した場合は加工を中止します。

接触許容差の拡大、形状の膨張、穴埋め、微小部品の削除、壁厚や半径の変更は行いません。離れた複数のソリッドを含む結果は、同じ分離数のまま扱います。単一入力だけのコピーは、結合を伴わないため従来どおりです。

## 適用経路

既存の共通結合APIを使用するボディ結合、押し出し、ミラー、配列、リブサポートなどに適用します。従来直接結合していた対称テーパー押し出し、複数面の薄い押し出し、旧履歴の押し出し再計算、パイプ、領域の回転形成、内ねじの円筒調整も共通APIへ通します。

ボディ回転形成では、生成途中の回転面に専用の面整理が必要です。共通APIへ `prepareResult` として専用処理を渡し、独立コピー上で専用整理を完了してから共通検査を行います。未完成の中間形状を完成品として検査して再回転を止めることを避けます。専用ねじ結合などの固有処理を一律に置き換えるものではありません。

保存済みのBREPは開くだけでは変更しません。旧モデル用のシェル・フィレットなどの復旧処理も保持します。メッシュの全トポロジー検査は従来どおりSTL出力時にも実施します。

## 回帰検証

```powershell
npm test
npm run build
node tests/union-followup-commands.mjs
node tests/union-followup-browser.mjs
npm run test:commands
```

ネイティブ試験では2つの箱を結合し、不要な継ぎ目が消えて6面・12辺になることを検査します。その結合からシェル・フィレット・同一高さの円柱による切り取りへ進む3経路について、解析的な体積、プレビューと確定、STLの閉鎖性、その後の断面分離、保存読込、履歴の強制再計算を確認します。実在する隙間と小さな別部品の保持、入力キャッシュの保持、周期面の継ぎ目を壊さないことも確認します。

ブラウザー試験では実際の結合と面選択から壁厚2 mmのシェルを作成し、6面への整理、STL出力、2段階のUndo/Redo、保存読込を確認します。旧モデルの失敗例についても、結合・再回転・断面分離・シェルの既存試験を実行します。回転結合と再回転の失敗例を代表コマンド試験にも追加し、共通処理変更時に継続検証します。
