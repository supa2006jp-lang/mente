# 加工の失敗表示・連続検証・確定結果の照合

## 失敗表示

- 切り取りで材料が減らない場合、ボディ間の最短距離を調べる。離れていれば隙間を mm で表示し、距離がゼロでも削れる体積がなければ「境界に接するだけでは削れない」と表示する。対象・方向・距離の確認を案内する。
- 単一対象の押し出し切り取り、ボディ間の切り取り、パイプ切り取りで測定する。すき間付き切り取りでは加工前ツールとの距離を加工後の隙間と誤認しないよう、距離表示を省略する。
- 無効な面・辺参照、内部を横切らない分割平面、滑らかな継ぎ目、有効なソリッドを作れなかった場合を区別する。
- 移動後の体積変化や無効ソリッドの検査では、その検査に失敗した形状の範囲を赤枠で示す。赤枠を原因の辺の特定とは表現しない。
- シェルの局所的な原因を特定できていない場合は、壁厚だけが原因だと断定しない。原因に合った案内がある場合、一律の「半分にする」「1 mm延長する」ボタンは出さない。

## プレビューと確定の照合

CAD計算済みのプレビューについて、加工後の体積・立体の分離数・位置と大きさ・出力ボディと削除ボディを記録する。同じモデルと同じ入力の確定結果を、モデルやUndo履歴へ反映する前に照合する。

- 体積は表示用三角形から推定せず、既存のCAD検査結果を利用する。照合のための追加のCADブーリアン計算は行わない。
- 寸法、対象、方向、選択面などが変わった入力や、別のモデルの古いプレビューとは比較しない。プレビュー時と確定時で変わる新規IDは対応付ける。
- 押し出しの精密プレビュー用Workerと確定用Workerの間でも、小さな検査値だけを共有する。ボディ形状や表示メッシュのコピーを追加で保持しない。履歴ごとに最大8条件を保持する。
- 保存済みプレビューを直接採用する加工キャッシュでも、採用前に記録値を照合する。
- 不一致なら適用せず、違った検査値を表示する。加工キャッシュで不一致が発生した場合もプレビューを解除し、変更前のモデルと入力条件を「失敗時の記録」に保存する。
- 簡易プレビューは対象外。最終の干渉検査を省略するコイル接合の途中プレビューも比較しない。履歴の再編集は、後続工程を含む結果と置き換え工程単体を誤比較しない。既存の精密結果の再利用とキャッシュ採用検査を使う。

これは形状の代表値の照合であり、同じ体積・範囲・分離数を保った局所的な変形まで全て検出するものではない。CADの有効性検査とSTL出力検査も継続して使う。

## 連続加工の回帰検証

`npm run test:sequences` で次の7ケース・計32操作を実行する。

- フィレット → 押し出し結合 → 切り取り：寸法を変えた3ケース。
- 回転体2個 → 結合 → 断面分離 → 90°回転移動：180°と360°の2ケース。
- ミラー → 結合 → 同一高さの円柱による貫通切り取り：寸法を変えた2ケース。

各段階で解析的な期待体積、ボディ数、CADの有効性、閉じた出力メッシュ、精密プレビューとの一致、入力の保持を確認する。保存・再読込、全履歴の強制再計算、以前の履歴への復帰も検証する。意図的に体積を変えた結果が照合で拒否される対照試験を含む。

代表コマンドの `npm run test:commands` とGitHub Pages用ワークフローにも連続検証を組み込む。

`tests/command-verification-browser.mjs` は隔離したEdgeで、実際の加工プレビューを表示した後に検査値を意図的に変え、確定が拒否されることを確認する。元モデルと履歴、失敗記録、プレビュー再計算後の正常な確定、Undo/Redoまで検証する。ユーザーが開いているタブやモデルは使用しない。
